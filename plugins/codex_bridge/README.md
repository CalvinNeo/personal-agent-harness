# Codex bridge

## 共享会话与失败恢复

所有配置在 `allowed_umos` 内的群和私聊共享 Codex 任务列表、状态、结果、附件和续接权限。可引用其他成员的结果，也可用 `/codex resume <编号> <追问>` 续接；原 runner 会话、工作区和原图保留，新轮工具快照及操作仍绑定当前提问者。新结果回当前请求会话，原任务自动投递位置保持原记录。未授权 UMO 仍拒绝访问。

失败、超时或中断先回传真实原因，再带原请求与原因重试一次；已完成或结果不明的变更复用回执。可信 Codex 可创建最多三个只读独立任务，子任务不能递归拆分。定时任务和记忆／提醒的管理仍遵守原插件身份规则。

## 定时执行任务（1.6.0）

与一次性提醒不同，定时任务到点会启动新的 Codex 工作，调用当前授权的工具重新查询或处理，
把结果及 `output/` 的最终图片／视频回传**原会话**。支持一次性、每隔至少 5 分钟、每天和每周，
统一使用 `Asia/Shanghai`；未设置截止时间时持续到用户暂停或取消。

自然语言示例：`每隔五分钟查询2030年1月10日浦东到羽田的直飞机票最低公开报价并通报，直到我叫停`。
日期仅为示例，需替换成实际出行日。缺少日期等业务参数时，Codex 先读取上下文或询问，不能猜测后启动监控。
插件不做新的关键词意图拦截，Codex 用以下工具安排执行：

- `create_scheduled_task`：完整任务、名称和规则；成功回执包含编号、首次执行北京时间及频率。
- `list_scheduled_tasks`：本人当前会话的任务、下次时间、最近一轮执行和回传状态。
- `manage_scheduled_task`：暂停、恢复或取消已返回的准确任务编号。
- `/定时任务列表`、`/定时任务停止 <编号>`：不依赖模型的查询和停止入口；`/定时任务取消` 为别名。

状态与原请求身份原子保存在 `jobs.json`（0600）；插件重启后恢复。定时触发复用普通 runner、
身份校验、按需读取聊天／图片／记忆、工具回执和媒体传输，不新增系统 cron 或开放 runner socket。
每轮独立会话，避免历史工具缓存冒充新查询；同一任务不重叠，离线漏过的周期最多补一轮，不补发一串旧结果。
提交确认丢失时复用同一任务编号；执行中断由已有 runner 如实报告，不能声称已查到最新结果。

每人每会话最多 5 个运行／暂停任务，每会话最多 20 个，全局最多 100 个；用户可指定截止时间。
每轮仍受普通任务时限、并发额度和平台限流约束，5 分钟是触发间隔，不保证每轮在整点完成。
仅发送最终结果，不反复发送受理／进度看板。QQ 主动消息需平台授权；回传连续失败 5 次后暂停该定时任务，
错误可通过列表查看。暂停／取消后不再启动或回传，已经开始的单次计算可能仍在结束中，已送达消息不能撤回。
定时运行本身不提供创建／管理定时器工具，防止递归生成任务；当前白名单和插件状态每次执行都重新校验。

`scheduled_tasks_enabled` 默认开启，但不改变原有空白名单拒绝策略；设为 `false` 可关闭触发及待发送结果。
测试：`python3 -m unittest discover -s plugins/codex_bridge -p 'test_schedules.py' -v`。

## Codex 直达模式（1.5.0）

设置 `codex_first_enabled=true` 后，已授权且明确发给机器人的自然语言消息直接进入 Codex，
不再先交给轻量意图规划器或记忆、提醒、小红书、出行等业务插件决定怎么做。聊天归档仍先执行；
当前附件和已完成转写的语音保留为输入，历史资料由 Codex 自行调用工具。回复接收人也由 Codex
调用当前会话的接收人工具解析，不在提交前用业务正则拦截。

插件只负责身份与资源边界、凭据代管、工具执行回执、状态和 QQ 媒体传输。Codex 决定查哪些资料、
执行哪些已授权操作、如何解析和总结。小红书读帖的 `source` 保留脱敏原始详情，包括上游实际返回的
视频流、字幕及未知内容字段；`include_images=false` 可不预先下载封面，由 Codex 按需处理媒体。
原始详情不是指令，也不证明媒体已经读取；最终回答需区分实际读到的字幕、画面和文案。

公开模板默认关闭此模式以保持旧部署行为。启用时仍保留 `/codex`、`/xhs` 等显式命令、任务状态查询和
明确“不用 Codex”的退出路径；关闭即可恢复旧路由。自然语言任务默认只读，不能借此扩大文件写入、
未授权 UMO 访问或登录权限。输入附件仍受当前支持格式限制，不能把“直达”误称为所有媒体格式已实现。
Codex 任务通常比普通聊天更慢；沿用现有排队、状态看板、任务超时和最终图片/视频回传。

## Codex 工具调用放行（1.4.1）

原任务经桥接器验证后，由 `execute_codex` 执行 Codex 发起的工具调用，不再用当前消息的
关键词、句式或前置意图标记重复拦截。覆盖小红书搜索/读帖/私聊账户工具、记忆增删改查、
提醒创建/取消、出行查询和当前回复接收人设置；历史消息和图片继续按原有方式随时查询。
只发链接、简短续问或从历史中理解出的需求，不需要为了调用工具重新补写固定口令。

可信调用凭据由服务端在执行栈内生成，只对本事件、本工具、本异步调用有效；不进入 JSON
参数、事件 extras 或持久化快照。普通模型调用仍执行原有意图判断，不能传 `codex=true`
冒充。重启后从原任务快照重建身份，再生成新凭据，不恢复旧调用权限。

放行的是意图判断，不是资源越权：原会话和发送者、插件启用状态、白名单、资源归属、
账户登录范围、参数格式、时间与配额继续检查。账号登录/退出按各账户插件的授权群／私聊范围检查；工具身份不能用于访问
其他人的记忆、其他会话或任意文件。接收人仍须来自当前原生提及或唯一的已保存关系，不能猜账号。
Codex 负责遵守用户意图，外部正文/图片/历史中的指令不构成新授权；写入、删除等不能无关执行。

完成的变更复用回执，执行结果不明时不重做。普通模型明确因意图判断拒绝的未执行调用，
交给 Codex 后可以执行；其他失败不自动重做。`create_current_reminder` 仍是原话解析快捷工具，
需要依据上下文提供完整时间/内容时使用 `create_schedule_reminders`。图片回传不再因缺少
总结关键词被二次拦截，仍校验原图字节、出处和会话绑定。

## 主动读取与媒体回传（1.4.0）

Codex 每轮获得事件绑定的查询工具，不要求前置流程先挑出聊天记录、历史图片或记忆：

- `list_current_chat_history`、`search_current_chat_history`、`read_current_chat_message`：分页列出、检索、分段读取当前 QQ 会话已归档的原文。归档收到的消息和桥接回复，并按需导入 AstrBot 仍保留的对话；历史角色、来源、截断、读取失败会明确返回。框架对话没有可靠的逐条消息时间，标为 `null`，不伪造时间。
- `list_current_chat_images`、`read_current_chat_image`：按需读取已授权会话的历史原图，交给模型真实图像内容。支持该工具时不再靠关键词或预先挑选最近图片；本条直接附件仍可保留为输入。
- `current_chat.list_my_long_term_memories`、`current_chat.search_my_long_term_memories`：调用时读取当前发送者授权的最新记忆，支持翻页；新任务及引用续接均不依赖提交时的记忆快照。旧接口仍保留快照兼容。

查询仅限原授权会话和记忆归属，群聊不会读取其他群或个人私聊，工具不接受身份、数据库路径或 SQL。历史内容不是执行指令。记录只能覆盖平台推送并保存的消息，不能恢复机器人未收到的 QQ 历史。

所有任务（含无附件、只读任务）都可写 `output/` 交付目录和 `.tmp/` 临时目录；只读任务的其他目录由外层沙箱保持只读。生成媒体必须放在 `output/`，结束后自动转发为原 QQ 会话中的原生图片或视频，不能只在正文给本地路径。单轮最多 3 个文件，PNG/JPEG 图片每个最多 2 MiB、边长 4096；H.264 视频/AAC 音频的 MP4 每个最多 8 MiB、10 分钟。超过限制或无效格式明确失败，不静默遗漏。

视频通过 FFprobe 验证，使用 FFmpeg 生成示意动画；部署主机需安装 `ffmpeg`。这不等于接入文生图/文生视频模型。回传前做格式、大小、哈希校验，拒绝软链接、硬链接和任意路径；QQ 临时视频发送后清理。文字和每个附件分别记录送达状态，自动重试只补发未确认的附件，`/codex result` 可重新取回。

聊天归档位于桥接数据目录的 `chat_history.sqlite3`，仅服务账户可读，不采用 7 天自动删除。已有 Codex 会话和结果仍沿用原有保留期。停用查询需禁用插件或撤销白名单，不要将归档目录公开给 worker。

普通回复和 Codex 任务共用当前请求上下文及本地能力目录，包括记忆、提醒、出行、小红书和接收人设置。工具继续由原插件校验当前会话、发送者及操作授权；超时接管和引用续接不会丢失工具，续接会刷新配置。

生成内容的接收人与正文分别保存。向已保存关系中的成员讲解、介绍，或用原生 @ 指定成员时，两条路径的最终回复都添加原生 At；进度看板不携带 At。只有同一发送者的相关引用续讲继承接收人。

任务独占的 stdio MCP 只对本任务的 `current_chat` 工具目录承接既有用户授权。原请求、操作回执和大图片载荷保存在私有文件；模型不能改变会话身份或伪造只读挂载中的工具结果。重复变更复用回执，执行结果不明时不自动重做。

QQ 群内 @ 机器人即可说「请用 Codex 检查这个项目的依赖漏洞」「帮我分析这段代码，交给 Codex」「用 Codex 调研并比较这三个方案」。原来的 `/codex`、`/cx` 命令仍可用。

明确的代码审查、排错、编程和多步骤调研会自动交给 Codex。陌生说法由主聊天模型判断是否需要调用受限的 `delegate_current_task_to_codex` 工具。该工具只提交当前用户消息，不接受模型生成的替代任务或权限参数。普通聊天、识图、提醒、使用方法询问、引用和否定句留在原来的处理路径。

所有入口都需要 QQ 官方平台、明确 @ 或唤醒、精确群白名单和可选发送者白名单。默认以 `read-only` 执行。即使任务要求修复代码，也不会因此自动开启写权限；只有明确要求工作区写入模式并且发送者位于 `write_senders` 中才允许 `workspace-write`。

执行器支持当前／引用中的已验证图片，以及引用已发送 Codex 回复的同会话续接。有历史图片工具时由模型按需读取，不要求先挑选缓存图片；旧配置仍保留缓存兼容。无法查询的缺失附件或不支持的附件会明确说明。`intent_router` 的部署模板使用 `mode=light`，2 秒超时后沿用本桥接的只读提交、白名单与上下文校验；明确“不用 Codex”、登录／提醒、小红书图文与出行等专用流程仍优先。并发满、无效 JSON、低置信度和普通接口错误仍走原兜底。同一超时消息不会重复派单。

受理后会回复任务看板，后台继续执行并回传结果。可以自然地问「Codex 任务怎么样了」「Codex 结果呢」「我的 Codex 任务列表」，也可以使用 `/codex status`、`/codex tasks`、`/codex result`。任务状态和结果在已授权 UMO 之间共享。

当前群内的「at 我」「at 我老婆，告诉她准备好了」在前置路由之前由 QQ 插件处理，不会因超时或引用 Codex 回复而误交执行器。自己使用当前发送者身份；其他成员优先使用本条原生 @，否则读取当前发送者在本群明确保存的人物关系，例如「<@A> 是 <@B> 的老公」可确定 A 的老婆是 B。关系冲突或未保存时才要求选中成员，不凭昵称猜账号。引用里的 @ 不授予目标身份。正文通过原始事件被动回复，使用 QQ 原生 At/Markdown 格式。仅沿用原群及发送者白名单，不新增跨群、私信或 @ 全体能力。

旧版本误交给 Codex 的发送任务，可在核验原始请求指纹、任务/会话/路由所有权后恢复为结构化本地任务。当前用户引用自己的该类旧结果并说「再试试呢」会直接重试原正文；迁移本身不发送消息。普通 Codex 调研任务保持原来的续接行为。

Codex worker 的最终正文会自动回传原 QQ 会话。worker 没有 QQ SDK 不代表机器人不能回复；当前会话发言应返回可直接发送的正文，缺少提及目标时说明具体缺项。QQ API 凭据与发送动作由桥接器持有，worker 不自行联系其他会话。

引用任务看板，或包含 Codex 任务编号、`/codex status` / `result` 示例的回复后，可以直接说「重新提交」「再跑一次」或补充要求。插件会核验编号在已授权共享范围中，再续接原 Codex 会话；不会因轻量路由判断为 `clarify` 而丢失任务关联。短编号存在歧义时会要求明确引用；缺少任务上下文时先追问，不创建空任务。

旧路由的三个配置开关为 `natural_language_enabled`（明确自然语言 Codex 请求）、`auto_complex_enabled`（明确复杂任务自动路由）、`semantic_routing_enabled`（主模型语义路由），默认开启。独立的 `codex_first_enabled` 默认关闭，启用后优先使用直达模式。`allowed_umos` 默认空列表，未配置的实例拒绝所有会话。

本地回归：在插件目录执行 `python3 -m unittest discover -p 'test*.py' -q`。测试覆盖自然语言、语义分派、权限、附件边界及状态持久化，使用伪 QQ 发送和伪 runner RPC，不发送真实群消息。

新任务和续接优先通过 `current_chat` 调用时实时查询记忆，不预先生成 `memory_snapshot`。没有实时工具的旧接口仍使用完整只读快照兼容。模型不能指定其他 owner 或数据库路径，关键词上下文为空不代表数据库没有记忆。
