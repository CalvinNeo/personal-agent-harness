# xhs_search

这个插件通过本机只读服务搜索小红书。使用二维码登录一次后，登录 Cookie
保存在小红书服务的受限目录；QQ 消息中不接收、不保存小红书 Cookie 或账号
token。插件只从 root 管理的本地文件读取服务 API token。

## 一次性配置

1. 在服务器上部署只监听 `127.0.0.1` 的小红书服务，并完成其本地 API token
   和 Cookie 存储配置。服务必须提供 `search`、`login_qr`、`login_status` 和
   `logout` 接口。
2. 由 root 写入 `/etc/xhs/api-token`，目录设为 `root:xhs-secret 0750`，文件
   设为 `root:xhs-secret 0640`，仅 AstrBot 和小红书服务用户加入该专用组。
   不要把文件加入仓库、日志、Prompt 或任务正文。
3. 在 AstrBot 配置中精确填写允许的 QQ UMO。`login_umos` 必须是管理员的
   QQ 私聊 UMO，`login_senders` 必须是管理员发送者 ID；两者均为空时登录
   被拒绝。搜索会话由 `allowed_umos` 控制，`allowed_senders` 可选进一步收窄。

示例（没有任何真实凭据）：

```json
{
  "allowed_umos": ["qq_official:GroupMessage:approved-group"],
  "allowed_senders": [],
  "login_umos": ["qq_official:FriendMessage:operator"],
  "login_senders": ["operator"],
  "endpoint": "http://127.0.0.1:18060",
  "api_token_file": "/etc/xhs/api-token",
  "timeout_seconds": 90,
  "max_results": 5
}
```

## QQ 命令

管理员在白名单私聊中发送 `/xhs login`，机器人回传二维码；用小红书 App
扫码后，发送 `/xhs status` 确认登录。发送 `/xhs logout` 可删除服务侧登录态。
在允许的群中使用 `/xhs search <关键词>`。登录命令只在精确的管理员私聊 UMO
中有效；群聊、非白名单发送者和其他平台均静默拒绝。

旧的 `/xhs auth <token>` 不再保存或处理消息中的 token，只会提示使用二维码
登录。插件拒绝命令不能删除 QQ 历史或框架预先记录的日志，因此不要发送真实凭据。

开启 `intent_router` 的 `light` 模式后，模型可以识别没有固定句式的“小红书
搜索”请求。路由器确认的 `xhs_search` 任务直接执行；其他自然语言请求也可由
主模型通过仅绑定当前消息的搜索工具识别。两条路径都由本插件执行会话白名单
和服务端登录校验；它不会执行发布、评论、点赞或收藏操作。

## 登录状态和私聊搜索

“已登录，检查下小红书的登录态”由本机状态接口处理，不委派给 Codex，
也不需要开启 Computer Use 或发送截图。扫码等待期间，“我已经扫码确认了”
和“再看下”只检查原扫码会话，不生成替代二维码。没有明确小红书上下文时，
普通“已登录”不会当成小红书账户操作。

`xhs_login_status()` 是无参数只读工具，仅提供给精确允许登录的私聊账户。
返回状态区分已登录、等待 App 确认、无可用登录态和检查失败；检查失败不等于
用户没有扫码。二维码会话有效期内重复请求返回等待提示，服务重启会中断扫码，
应等持久化成功后再维护服务。

登录与搜索授权仍然独立。允许管理员私聊搜索时，必须将该私聊 UMO 另行加入
`allowed_umos`；只有 `login_umos` / `login_senders` 不会自动获得搜索权限。
没有保存登录态时搜索明确返回登录提示，不把无结果、未登录和服务故障混为一谈。

## 分享链接读取

在允许的会话中发送完整小红书分享链接并说“给我总结下”，即可直接读取该笔记，
不要求先搜索，也不要求文字中额外写“小红书”。支持官方 HTTPS 链接中的
`/explore/<笔记ID>` 和 `/discovery/item/<笔记ID>`，包括明确引用的链接。
`xsec_token` 是分享链接里的笔记访问参数，不是账号 Cookie；只在服务端解析和使用，
不加入工具参数或返回值，不接受任意网站、账号密码或任意笔记 ID。

当前消息里的链接优先于旧搜索或引用；工具仍检查原会话和发送者。普通模型路径还校验
明确读取意图；经桥接器验证的 Codex 工具调用不再重复校验关键词，可直接读取完整链接或
本用户搜索得到的引用。缺少链接访问参数时
提示补充完整分享链接，不误报需要重新登录。普通模型路径仍只返回文案与封面，
不把它们当成完整视频画面、音轨或逐字稿。

## Codex 自行处理原始内容（2.2.0）

可信 Codex 调用 `xhs_read_notes` 时，除兼容的简要字段外，还返回 `source`：
本次详情接口实际返回的脱敏结构，包括完整文案、视频清晰度与播放地址、字幕资源、
已返回的评论和未知内容字段。不预先规定只能看封面，也不由插件实现视频总结流程。
默认仍可返回原帖图片；`include_images=false` 只关闭图片预下载，不移除原始资源信息。
只准备搜索引用时该选项也会保留在 `next_arguments` 中。

Codex 自己决定是否读取字幕、下载视频、抽取画面或处理音轨；下载与分析能力来自 worker
现有工具，不表示每种媒体或转写服务都已接入。原始详情是非可信数据，媒体地址不是观看证明。
资源元数据中有字幕语言也不代表字幕下载成功，回答必须标明实际读取范围。

接口仍只允许原会话当前发送者的分享/搜索引用，不开放任意后台 API、发布或账号凭据。
`source` 递归删除 Cookie、授权头和账号敏感字段，去除分享访问参数及其回显；详情结构过深
或异常时明确失败，不静默截断后声称完整。资源签名保留供当前任务下载，不在 QQ 正文公开。
原始详情受现有接口 2 MiB 响应上限约束，且未加载全部评论。凭据继续仅留服务端。

Codex 可按任务需要使用搜索、读帖和状态工具；登录、退出仍只在原有授权私聊提供。
调用来源只能由服务端验证，工具参数不接受身份或信任标记。实际登录失效、不可访问笔记、
无效参数和服务限流仍如实返回，不绕过第三方权限。
