# QQ 长期图片上下文

配置 `archive_dir` 后，机器人收到的原图和用户直接引用的图片会保存到长期图片档案。图片没有 30 分钟有效期，不因重启、临时文件清理或超过最近 12 张而删除。按图片内容去重保存文件，SQLite 保留原消息、时间和引用关系。

群聊共享本群已收到的图片；私聊图片只在原私聊可读，不会出现在群聊或其他私聊。仅在 `allowed_umos` 授权的会话启用，`allowed_senders` 可继续限制调用者。引用图片是当前用户提供的资料，不推断原作者，也不递归获取转发或嵌套消息。

普通识图和 Codex 共用档案与工具：

- 当前上传优先，其次直接引用的原图或可核实的原消息索引；本条图片数量不足时不拿旧图补齐。
- 没有新上传时，最近一批图片会自动带入后续问题，包括“能估算楼层么”等没有“图片”字样的提问。历史图片不代表当前状态。
- `list_current_chat_images` 返回图片编号与接收时间，用 `next_cursor` 翻页查看更早的图片，没有历史总量截断。
- `read_current_chat_image` 返回真实图片内容供模型查看，不能传入任意文件路径、URL、用户或会话。工具在普通模型与 Codex 中均可用。
- Codex 每次自动附图最多 4 张，其他历史图片可通过工具逐张读取。原图完整保存，给模型的视图限制为 1600 像素边长、512 KiB JPEG。

推荐把图片和 @机器人 放在同一条消息里发送。QQ 若没有向机器人推送上一条普通图片，后续文字 @ 无法补收；可以直接引用原图再 @。QQ 仅传引用标识时，插件按同会话已保存的消息索引恢复原图；尚未保存的消息会明确说明缺少图片。

档案目录权限 `0700`，原图和索引 `0600`，拒绝符号链接及超出 20 MiB 的输入。日志只记录数量、来源和范围散列。不要将档案、聊天数据库或配置提交到 Git。`cache_file` 是兼容旧版的短期引用缓存；长期访问由 `archive_dir` 负责。

升级已有实例时，可在停机期间运行 `scripts/backfill_image_history.py`，从原会话数据库与经过身份核实的 Codex 图片记录回填仍可读取的历史原件。脚本只读源数据，不跨会话推断文件来源；QQ 从未推送且服务器无原件的图片无法凭空恢复。

验证：

```bash
python -m unittest discover -s plugins/image_context -p 'test_*.py'
python tests/test_image_context_runtime.py
python tests/runtime_durable_image_history.py
```

真实框架测试使用独立临时 `ASTRBOT_ROOT`，不发送 QQ 消息；覆盖原件保存、过期与重启、临时文件删除、群与私聊边界、普通/Codex 原生图片工具和完整分页。
