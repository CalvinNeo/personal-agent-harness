# QQ 图片上下文

在允许的群里发送一张或多张图片，然后 @机器人说：

- `帮我看看上一张图`
- `总结刚才三张图`
- `对比一下刚发的那几张图`
- `能看到新发的图么`
- `再看看，有收到新图么`

发图后 2 分钟内，`看看这是什么`、`这个是啥` 等简短问法也会自动带上同群同发送者最近一批图片，不需要 QQ 的引用功能。两分钟后请明确说“刚发的图”“新图”等；明确引用仍在 30 分钟有效期内可用。读取图片不会延长有效期。当前消息直接附图时，宽泛问法优先使用当前附件。

插件只记住 QQ 官方平台实际推送的顶层图片。QQ 若未推送普通群消息，需要发送图片时也 @机器人。明确引用 QQ 消息时，插件只读取该条 `Reply.chain` 的直接图片附件，不递归转发/嵌套消息；因此引用附件本身可用于分析，即使原图已超过缓存 TTL。

连续上传（相邻上传间隔不超过 2 分钟）的图片视为一批；“那几张图”选最近一批，“三张图”选最近三张。找不到或数量不足时，直接提示重发，不请求模型猜测。

只在 `allowed_umos` 授权的群启用，默认空列表拒绝所有群。可通过 `allowed_senders` 进一步限制发送者。缓存按完整群会话 UMO 和发送者分开，30 分钟有效，每人每群最多 12 张，总共最多 64 个发送者会话。缓存 QQ 图片域名的 HTTPS URL，以及 AstrBot 预处理生成的临时图片文件引用。后者必须位于 AstrBot 临时目录内，拒绝符号链接、非图片文件和超过 20 MiB 的文件；文件被清理后提示重发。运行日志不记录 URL/文件名。配置 `cache_file` 为绝对路径后，插件会以原子写入保存受限快照，缓存文件权限为 `0600`，仅保存已授权会话的图片引用和时间信息，不保存消息正文、模型内容或图片数据；重启会恢复尚未超过 30 分钟 TTL 的引用，并扣除停机时间。`cache_file` 留空时不落盘。被动收到图片只缓存，不额外回复。

后续提问必须 @机器人或使用既有唤醒方式。发送给普通模型的历史图片使用 AstrBot 临时消息组件，不加入持久化聊天历史。AstrBot 本身可能为模型准备临时图片文件，其处理行为由框架管理；此插件不改变原有群会话是否共享的配置。模型仍需支持图片。

验证：`python3 -m unittest discover -s plugins/image_context -p 'test_*.py' -v`。

日志记录 `Image cache received=N accepted=N scope=...`、`Image context selected=N mode=explicit|implicit scope=...`，以及有最近图片但问法未匹配的 `Image context skipped reason=no_reference scope=...`。scope 是会话与发送者的哈希，不含图片内容。真实 AstrBot 预处理回归见 `tests/runtime_history_repairs.py` 和 `tests/test_image_context_runtime.py`；使用合成图片验证多图及最新图片，不提交实际聊天或用户图片。执行环境见 `docs/TESTING.md`。
