# 闲鱼搜索、登录与新商品提醒

`xianyu_watch` 在精确授权的 QQ 群聊或私聊提供扫码登录、状态检查、即时商品搜索和新商品监控。安装独立浏览器服务、配置和验收见 [闲鱼部署说明](../../docs/XIANYU.md)。

- `allowed_umos=[]` 拒绝全部查询和监控；`login_umos=[]` 拒绝全部登录操作。还需同时满足 AstrBot 主白名单。
- 示例开启 `shared_login_members`：同一个已批准登录会话内的成员可以获取二维码和查询状态。关闭此项后，登录同时要求精确匹配 `login_senders`。
- 在已授权会话说“闲鱼登录”或 `/闲鱼 login` 获取原生二维码。扫码并在闲鱼 App 确认后，用“闲鱼登录状态”或 `/闲鱼 status` 查询平台真实状态。已有登录上下文时，“扫好了”“好了么”也查询状态，不重发二维码。
- `xianyu_search` 直接投递实际商品清单，名称为可点击的规范商品链接，并保留结构化结果供比较；默认不发送商品图片。二维码图片始终独立于 `send_product_images`。
- 明确要求定期监控时使用 `create_xianyu_watch`，默认每 30 分钟。首次成功查询保存全部商品的名称、标价、链接和观察时间，之后只提醒首次发现且符合条件的商品；搜索失败不会记为零结果或初始化基线。预算必须传入工具的 `max_price`，按严格小于上限执行；面议、范围、定金、运费等不确定总价不会当作符合预算。
- `/闲鱼 list` 查看共享授权范围中的监控，`/闲鱼 read 编号` 读取基线详情；`/闲鱼 pause|resume|cancel 编号` 暂停、恢复或取消。监控保留原创建人，所有已授权会话可共享列表、详情和管理；提醒始终投递创建时原会话，不能由模型改接收会话。

平台登录态没有保证的固定天数。账号 profile、私密恢复快照、监控基线和待发送队列保留在服务器，不进入模型上下文或 Git。群成员会共用同一个部署账号的登录态；不要通过 QQ 发送密码、Cookie 或服务 token。

`read_xianyu_watch` 用 `offset`/`limit` 分页读取完整基线，扫描总数与符合价格条件数分别显示。旧版仅保存 ID 时明确返回详情不可用；显式 `refresh_metadata=true` 只补查询中仍能找到的原 ID，并标记当前恢复时间，不冒充首次快照、不发送消息。`manage_xianyu_watch(action="update")` 可更新预算、检查间隔和每词结果数；保留原基线、已见 ID 和投递目标。仅更新预算时保留原下次检查时间，不额外触发一轮查询。

用户问“基线有哪些商品”或要求完整清单时使用 `show_xianyu_baseline(watch_id, matching_only=true)`。工具按已保存数据完整筛选并直接发送全部匹配商品，每页最多 10 件、UTF-8 不超过 3500 字节，每件含完整商品名超链接和真实标价。长标题只增加页数，不截标题或链接；页首包含监控状态、检查间隔、预算及详情来源，补查条目明确标注。工具仅回短投递计划，桥接器逐页确认、记录进度；确认全部送达后才可简短回复完成，模型不再重复摘要或省略清单。`matching_only=false` 展示全部基线 ID，未恢复详情继续标未知。

搜索、基线展示与新商品提醒共用同一安全 Markdown 格式。商品名称中的标记被转义，链接只由数字商品 ID 构造；不采用商品文字自带的外部链接。默认不把清单转成图片。
