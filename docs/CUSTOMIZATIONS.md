# 自定义修改清单

这个仓库整理了围绕 AstrBot 4.29.3 的自定义代码、系统服务模板和运维工具。它是经过脱敏、参数化的参考版本，不是服务器目录的完整备份。线上已有的授权群、用户、模型提供商地址、凭据和运行数据需要在部署机器上另行配置。

| 范围 | 代码位置 | 修改后的行为 |
| --- | --- | --- |
| 本地提醒 | `plugins/reminder/` | 支持命令和明确的自然语言提醒，持久化单次任务，在到期时发送真正的 QQ `@` 提醒。 |
| 图片上下文 | `plugins/image_context/` | 暂存同一发送者最近的图片，使后续“刚发的那几张图”能够引用对应图片。 |
| Codex 接入 | `plugins/codex_bridge/` | 通过命令、自然语言和受限语义工具提交复杂任务，使用状态看板和原始 QQ 回执回传异步结果。 |
| Codex 会话续接 | `services/conversations.py` | 保存真实原生 session ID、按 owner 隔离原图和工作区；引用 Codex 回复时续接原会话。 |
| Codex 公开网页工具 | `services/public_web.py`、`services/public_web_mcp.py` | 专用 stdio MCP 提供公开搜索与 GET 读取；任务命令另有联网权限。 |
| 长期记忆 | `plugins/long_term_memory/` | 明确请求才写入 SQLite；按群与发送者隔离，相关条目注入普通聊天和 Codex 任务。 |
| 轻量意图路由 | `plugins/intent_router/` | `regex` 使用现有规则；`light` 用可配置 provider 的 low reasoning 做固定枚举路由，失败自动回退。 |
| 小红书搜索 | `plugins/xhs_search/` | 通过本机 REST 服务只读搜索；QQ 私聊扫码，Cookie 独立持久化；不接收聊天中的 token。 |
| Codex 执行进程 | `services/codex-runner.py`、`services/media.py` | 以独立低权限账户执行任务，校验 Unix socket 对端身份，限制工作目录、执行时间、图片和输出大小。 |
| 模型代理 | `services/codex-api-proxy.py` | 在本机代理模型请求，将上游模型密钥与 Codex 任务进程分开保存。 |
| AstrBot 内置功能修正 | `patches/`、`scripts/apply_patches.py` | 修正 AnySearch 区域参数，并移除模型限流重试日志中的密钥前缀。 |
| 部署与访问限制 | `deploy/`、`scripts/` | 提供专用账户的 systemd 服务、本机端口限制、默认拒绝的配置初始化及检查工具。 |

## 提醒：识别、调度与真实 @

提醒由本地解析器和调度器处理，不需要调用 Codex，也不需要模型来解释标准时间表达式。可以在授权群中 @机器人后发送：

- `两分钟后提醒我喝水`
- `请在半小时后提醒我开会`
- `提醒我明天下午三点开会`
- `/提醒 2分钟后喝水`
- `/提醒列表`
- `/提醒取消 <ID>`

解析器支持中文数字、半分钟等时长以及日期、时刻表达式，按 `Asia/Shanghai` 解释本地时间。只有明确的提醒请求才会创建任务；含糊时间、缺少内容以及暂不支持的请求会要求补充或说明限制。自然语言入口要求明确 @机器人或使用既有唤醒方式，避免普通聊天触发。转发、引用内容不会直接当作新提醒指令执行。

任务以原子写入方式保存为私有 JSON 文件，记录创建者、会话、时间和内容。重启后会重新读取待办任务。默认延迟范围为 5 秒至 7 天，默认每群最多 20 条、每人最多 10 条，每条内容最多 500 字；这是单次提醒，不是重复日程系统。

QQ 官方适配器在纯文本消息中会直接显示 `<qqbot-at-user ... />`。提醒消息单独启用 Markdown，并使用 AstrBot 的 `At` 消息组件，使 QQ 解析成真正的 @。这不要求把所有机器人回复都改成 Markdown。

发送时先尝试群消息接口，必要时使用仍在内存中的原始 QQ 事件回复。失败后间隔 30 秒重试，最多尝试 5 次；达到上限后移除任务。平台不可用返回 `False` 时会视为失败，不会误标为已发送。它不是“保证送达”队列，QQ 权限、回复时限、限流和网络故障仍可能影响结果。

## 图片：按发送者保存最近上传的引用

图片缓存按“完整会话 UMO + 发送者”隔离，默认有效期 30 分钟，每人每群最多 12 张，总共最多 64 个发送者会话。相邻上传间隔不超过 2 分钟的图片视为同一批：

- “上一张图”选择最近一张。
- “刚才三张图”选择最近三张。
- “刚发的那几张图”选择最近一批。

只记录 QQ 官方平台实际推送的顶层图片，不递归读取引用或转发图片。QQ 如果不推送未 @机器人的图片消息，发送图片时也必须 @机器人。图片不存在或数量不足时会提示重新发送。

缓存仅保留受支持 QQ 图片域名的 HTTPS URL，不由插件下载图片或写入文件，重启后清空。在后续图片引用请求中，插件去掉上下文中的历史图片，注入当前发送者选中的图片，降低混用他人图片的风险。注入使用临时消息组件，不额外加入持久化聊天记录；AstrBot 为调用模型所进行的临时文件处理仍由框架管理。

这项功能通过普通图片模型完成，不经过 Codex。提供商需要实际支持图片输入。缓存隔离也不代表群文字历史隔离：AstrBot 原有群会话中的文字上下文是否共享，仍由会话配置决定。

## Codex：显式执行与异步回传

`/codex <任务>`、`/cx <任务>`、明确的自然语言 Codex 请求和已配置的复杂任务路由可进入独立执行器。默认只读；`/codex write <任务>` 还需要发送者位于单独的 `write_senders` 白名单中。提醒和长期记忆操作由各自插件直接处理，不要求调用 Codex。

执行器使用 Linux Unix socket，校验连接进程的 UID。任务所有者由完整会话与发送者标识共同生成哈希，持久 Codex 会话按所有者隔离工作区、原图和 session。任务使用 Codex 的只读或工作区写入沙箱，以独立服务账户运行，同时限制任务并发、时限、输入和输出大小。systemd 与外层 bubblewrap 进一步限制可写目录、可见状态、权限与资源。

外层 bubblewrap 将根文件系统以只读方式挂载，并隐藏其他任务工作区和私有运行状态；宿主机其余文件是否可读还受文件权限（DAC）和 AppArmor 控制。Codex 探针确认 `codex-net-read` 不能写会话工作区或 `.tmp`；`codex-net-write` 可以写分配的会话工作区与 `.tmp`，不能读取或写入相邻任务工作区。带有本次或保留图片输入的任务沿用旧行为，自动切换到 `workspace-write`，以便生成图片结果。

长期记忆数据库属于 AstrBot 的私有状态，不因工作区写入授权而向 Codex 开放。

异步回传保留原始 QQ 事件，让适配器能使用原消息标识回复，修复直接用主动消息接口回传时被平台拒绝的问题。原始消息的有效期和平台配额仍然适用，长任务或进程重启后不保证可回传。

上游密钥保存在独立代理账户可读的私有文件中，由本机代理附加到模型请求。Codex 任务环境不直接携带该上游密钥。输出还会做有限的密钥模式脱敏，但不能把它当作通用敏感信息检测器。

任务命令通过按模式选择的 Codex 网络 profile 联网，公开网页访问仍可由下述受限 MCP 实现。模型请求仍会发送到配置的提供商；主机 root、可信 MCP 程序、服务配置和依赖供应链属于信任边界。升级 Codex、AstrBot 或 Linux 沙箱相关组件时，需要重新检查限制是否生效。

## Codex：搜索与读取公开网页

`public_web` 是由 Codex 启动的 stdio MCP 子进程，不监听 HTTP 端口，不保存密钥。它只注册两个工具：

| 工具 | 输入与结果 |
| --- | --- |
| `search_public_web(query, max_results=5)` | 通过 Bing RSS 搜索，返回最多 8 条标题、URL 和摘要。 |
| `read_public_web(url)` | 读取公开文本网页，返回正文、标题、来源 URL 及部分链接。 |

请求固定为 GET，不接受自定义方法、请求体、Cookie、Authorization 或任意请求头。只允许标准端口的 HTTP/HTTPS 主机名；解析出的全部地址必须是公网地址，连接时固定使用已经检查的地址，同时保留 HTTPS 主机名验证。每次重定向重新校验目标，阻止内网、回环、链路本地地址、IP 字面量和常见含凭据的 URL。页面正文最多 2 MiB，返回正文最多 14,000 字符，整个请求有时限并限制跳转次数。

网页和搜索摘要作为不可信资料返回，不能授权工具操作或覆盖任务规则。搜索关键词会交给 Bing；任务提示要求不把凭据和私人记忆放入查询。此工具不执行 JavaScript，不登录，不上传文件或提交表单；依赖登录、动态渲染、反爬验证的站点可能无法读取，搜索服务不可用时会返回明确失败。

Codex 配置关闭内置 `web_search`，设置 `features.network_proxy=true`。runner 对新任务及续接任务均选择对应的 `default_permissions`：`codex-net-read` 继承 `:read-only`，`codex-net-write` 继承 `:workspace`。两者都启用网络，设置 `mode="full"` 和域名 `*` 放行；文件写入范围仍按上述模式区分。

两个 profile 的 `allow_local_binding=false` 是 Codex 网络代理的本地/私网访问选项，不是单纯的监听端口开关；当前规则只配置 `*`，没有精确的 localhost 或私网 IP 放行例外。

MCP 的公开地址校验、DNS 固定与 GET 限制只覆盖这两个网页工具。命令联网并没有相同的网页白名单或请求方法限制，不能把它描述成“仅可读取公开网页”。任务提示要求不把私密数据、密钥或长期记忆发送到外部网络；提示约束不能代替网络层过滤。

## 长期记忆：明确请求与按用户隔离

在允许的群中 @机器人，使用“记住我喜欢喝茶”“以后回答简洁一点，请记住”“把关于饮料的记忆改成我喜欢咖啡”“忘记我喜欢喝茶这条记忆”“查看我的长期记忆”或“清空我的长期记忆”。列表分页显示，可用 `/记忆 list 2` 继续查看；更新和删除也支持列表中的 `#ID`。目标含糊时要求补充，明确的清空请求直接执行。

插件只读取当前消息的顶层文字，不遍历引用或转发内容。否定、示例、引用指令和能力询问不会被当作修改授权；模型工具也必须与原请求的动作、内容、目标一致。普通聊天不会自动写成长期记忆。支持确定性明确表达；未匹配的同义改写可能需要重新说明。

SQLite 使用完整会话和发送者组合的 SHA-256 作为 scope，所有查询与修改均限定当前 scope。每个 scope 最多 100 条、每条最多 1,000 字符；密码、密钥、令牌、私钥等常见凭据模式拒绝存储。数据库和辅助文件应为 `0600`，目录 `0700`，重启后保留记录。数据库及备份属于私有运行状态，不能提交 Git；哈希隔离不等于内容加密。

普通模型请求和 Codex 桥接从同一插件读取相关记忆：先验证 QQ 会话、发送者和 @/唤醒条件，再按中文双字与英文词匹配，兼顾回答格式偏好，最多返回 8 条、6,000 字符。桥接还受任务总长度限制。记忆以有边界的 JSON 背景资料提供，不授予权限。数据库只由 AstrBot 插件按已授权的当前用户请求写入；Codex 只接收筛选后的背景资料，没有数据库读写权限。关键词检索可能遗漏同义词。

记忆审计只记录操作、scope 哈希片段及数量，不记录正文。删除当前条目不会追溯删除普通聊天历史、已提交的 Codex 上下文或外部备份；敏感内容过滤也不是完整的隐私识别器。

## 两处 AstrBot 源码补丁

以原始 AstrBot 4.29.3 wheel 为基线，对已部署的 AstrBot Python 文件逐一比对后，发现两处差异：

1. `astrbot/core/provider/sources/openai_source.py`：模型请求限流重试时，用固定脱敏文本代替 API key 前缀日志。
2. `astrbot/core/tools/web_search_tools.py`：把 AnySearch 的 `global` 区域选项映射为接口接受的 `intl`。

普通 AstrBot 对话原有的网页搜索仍使用框架内置工具，启用配置及通用示例一并保留；Codex 任务使用上述独立的公开网页 MCP。搜索请求会联系对应搜索服务，结果随后进入模型上下文。

安装的 `qq-botpy==1.2.1` 中带分发校验值的 Python 文件与原始校验值一致，未发现该 SDK 的 Python 源码修改。仓库不重复收录整个 AstrBot 或 QQ SDK，也不把它们描述为自研功能。补丁仅适用于固定版本；升级时应重新比较和移植，不能盲目覆盖新版本文件。

## 默认关闭与未纳入内容

自定义插件均以 `allowed_umos` 精确匹配允许的会话，空列表拒绝所有会话。`allowed_senders` 是进一步限制：在已允许的会话内，空列表表示不再限制发送者；Codex 的 `write_senders` 空列表则表示没有人能使用写入模式。框架层的会话白名单与插件白名单都要配置，不能只修改其中一个。

管理后台和模型代理只监听回环地址，通过 SSH 隧道管理；Codex 执行器只暴露本机 Unix socket。部署模板使用专用服务账户、严格文件权限和有限资源，避免把执行器当作 root 运行。

以下内容不属于仓库资产：真实服务器地址、QQ 应用凭据、群和用户标识、模型密钥及私人提供商地址、管理后台密码、聊天与长期记忆数据库、提醒记录、日志、图片 URL、Codex 工作区和会话历史、SSH 密钥以及线上配置文件。仓库中的占位符和默认拒绝配置需要在目标机器上补全，不能直接复制线上私有目录来“补齐”。
